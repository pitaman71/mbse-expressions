# Test plan — python3

Scope: everything under `python3/mbse/Expressions` (the framework, the standard dialects ISO/IEC 11404, IEEE 754,
IEEE 1164 and Unicode, the Patterns, Python3, MATLAB, Excel, LaTeX, C, Cpp and SystemVerilog dialects, and the
translators between them) and cross-implementation conformance. The design reference is
mbse-basis [FEA-024: expressions as data](https://github.com/pitaman71/mbse-basis/blob/main/docs/features/FEA-024.md), with its capabilities; this plan and the TypeScript one mirror each other case for case, with the deliberate
differences of `../../docs/EQUIVALENCE.md`. mbse-schemas is tested in mbse-schemas. DIA and TRN use numpy, as a module
Python expressions import (`uv sync --all-extras`).

## Running

```sh
uv run pytest                 # every notebook under tests/ and tutorials/
uv run coverage run -m pytest && uv run coverage combine && uv run coverage report   # fails below 100%
uv run python -m mbse.Expressions.Conformance.write   # regenerate ../conformance/python3
```

One suite per notebook. Each markdown cell starting `<a id="XXX-NN"></a>` and its heading `XXX-NN · title` starts one
test case, the anchor the skill links; the following code cell is the case. Each tutorial step's markdown cell starts
likewise, with `<a id="Tnn.k"></a>` and its heading `NN.k · title`.
